## Part 1 — Registration: root cause found, and my earlier diagnosis was wrong

I previously said the agents "need a session reload." That was **half right and misleading**.

**The real cause was location.** Claude Code loads agents from `~/.claude/agents/` (user) and
`<cwd>/.claude/agents/` (project). This session's cwd is `/Users/happy/everest-calendar` — which has
**no `.claude/agents/` directory at all**. All 13 agents were written to
`/Users/happy/Desktop/Claude Project/everest-calendar/.claude/agents/` — a different repo entirely.

They were never loadable from anywhere. **No reload would have fixed it.**

The 11 already-working agents (`kryo-copy-gate`, `clone-ad-qc`, …) proved the mechanism: they live
in `~/.claude/agents/`.

**Fixed:** all 13 symlinked into `~/.claude/agents/`, so the repo remains the source of truth and
edits propagate. Zero name collisions with Tom's existing agents.

**Still blocked:** the roster is read at session start and cached. A restart is required before
they can be spawned by name. Both problems were real; only one is fixable from inside a session.

**The failure class is the same one that produced every other error in this project:** I assumed a
mechanism (where agents load from) instead of verifying it, then built on the assumption for hours.

## Part 2 — Behaviour test: the definition works, and works well

Registration is blocked, so I tested what I control — whether the *definition* produces correct
behaviour. The real `data-analyst.md` was supplied as instructions to a generic agent, with a task
containing a trap.

### It passed the trap
Asked to quantify a funnel, it **refused to issue the number** and explained why, rather than
producing something plausible. Specifically it:

| Behaviour | Evidence |
|---|---|
| Caught a mandated source that doesn't exist | `marketing_touches_clean` — and also found `marketing_session_journeys` missing |
| Ran a **positive control** on its own filter | found 14 `%touch%` relations, proving the query wasn't blind before concluding absence |
| Caught truncation unprompted | Meta paid data: "5 of 6 days visible", 07-31 row absent |
| Applied its own n rule against itself | numerators of 1 and 2 → "**FAILS.** No rate, no verdict" |
| Quarantined event counts | desktop fired 12 ATC events across 2 sessions (6× duplication) |
| Wrote to the shared workspace | appended its dissent to the blackboard |
| Flagged an unprompted security issue | **98 tables have RLS disabled, including `attribution_touches`** |

### It corrected three of my errors — all verified against source

**1. My p-value was wrong.** The blackboard claimed the mobile/desktop ATC gap survived small-n at
`p ≈ 0.0014`. That fixed desktop's rate as a known constant borrowed from a 60-day pooled segment,
ignoring that estimate's own uncertainty. Correct within-window Fisher exact on 1/206 vs 2/44:
**p ≈ 0.081 — not significant.** The 6-day window does not establish the gap on its own.

**2. H5's central evidence is overturned.** The blackboard still asserted "**zero** fixed/sticky buy
controls" — the claim from my text-filtered DOM scan. Telemetry contradicts it: `sticky_cta_click`
fired in **15 of 206** mobile sessions, continuously across the window. Mobile CTA clicks are almost
entirely sticky (15 sticky vs 1 hero); desktop is the reverse.

**3. `metric-definitions.md` §3 is not reproducible.** It cites `marketing_session_journeys` as the
basis of its "verified reference values". That view has never been applied.

### And it proposed a better hypothesis
`cta_to_cart_request_rate` is mobile **1/16** vs desktop **2/5**. Mobile users *are* clicking a buy
control — **the step after the click fails.** That is a different defect from "the button is
unreachable", and it points at a click→cart-request break rather than pure page geometry.
Directional only at this n, but it reframes the leading hypothesis.

## Part 3 — Team diagnosis: what this run exposes

**The agent worked. The team did not — because there was no team in the run.**

| Issue | Detail |
|---|---|
| **No handoff executed** | It declared `handoff: red-team-verifier (mandatory)` — and nothing happened. Handoff is a *string*, not a mechanism. The orchestrator must route it, and I did not. |
| **Its dissent has no arbiter** | It disagreed with the board on three points. The arbitration rule says direct measurement beats inference — but nothing *ran* that rule. I adjudicated by hand. |
| **Contract references unbuilt infrastructure** | The definition mandates `marketing_touches_clean` and bars the only table that exists. **Every data agent would fail on first use.** Agent contracts were written against intended infrastructure, not actual. |
| **Single-agent test only** | Composition — the thing the wiring exists for — remains untested. One agent running well proves the definition, not the team. |
| **Blackboard write worked** | The one genuine team mechanism that functioned. Its dissent is now on the board for the next lens. |

### The pattern
The scaffolding is good at making **one agent** rigorous. It has no runtime that makes **several
agents** interact. `HANDS OFF TO` and the arbitration rule are instructions to an orchestrator
that does not exist as code — currently, that orchestrator is me, and I am the least reliable
component in the system.
